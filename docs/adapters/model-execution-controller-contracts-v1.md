# Model execution controller contracts v1

`ModelExecutionControllerContractsV1` is the persistable contract bundle for the declarations required by `ModelExecutionControllerV1`.

It aggregates three already-versioned contracts:

1. `ModelExecutionCapabilitiesWireV1`;
2. `ModelExecutionProfileSetWireV1`;
3. `ModelExecutionEnvelopePolicyWireV1`.

The aggregate contract id is:

```text
elastic.model-execution.controller-contracts@1.0.0
```

The media type is:

```text
application/vnd.elastic.model-execution-controller-contracts.v1+json
```

## Validation order

Deserialization of the aggregate JSON validates JSON shape only. `into_validated()` / `ModelExecutionControllerContractsV1::from_json()` then replays the existing semantic contracts in dependency order:

```text
capabilities wire
      |
      v
validated capabilities
      |
      v
profile-set wire + capability identity/fingerprint
      |
      v
validated correlated profiles
      |
      v
envelope-policy wire + capability/profile-set identity/fingerprints
      |
      v
validated controller contracts
```

The bundle does not calculate substitute fingerprints, repair stale identity, or accept mixed provider/model declarations.

## Serialization

A validated bundle can be serialized with:

```rust
let json = contracts.to_pretty_json()?;
```

The emitted aggregate embeds strict wire forms generated by the existing `to_wire()` methods. Manual fingerprint copying is not required.

## Reload

Reload and full semantic validation are one operation:

```rust
let contracts = ModelExecutionControllerContractsV1::from_json(&json)?;
```

Unknown top-level fields are rejected by `serde(deny_unknown_fields)`. Nested contracts retain their own strict shape and version checks.

## Controller construction

The current-state controller can consume the revalidated bundle directly:

```rust
let controller = ModelExecutionControllerV1::current_state_from_contracts(
    "model-runtime",
    contracts,
    backend,
    telemetry,
    CadenceConfig::OneShot,
    ExecutionModeConfig::Apply,
)?;
```

For another existing forecaster, use `ModelExecutionControllerV1::from_contracts(...)`.

## What is not persisted here

This bundle intentionally does not serialize:

- a physical `ModelExecutionProfileBackendV1` implementation;
- a `ModelExecutionResourceTelemetryV1` implementation;
- GPU/CPU device handles;
- model weights;
- runtime process state;
- secrets or backend credentials.

Those remain live downstream integration objects. The persisted bundle describes only the already-qualified execution contract and resource-to-profile policy.
