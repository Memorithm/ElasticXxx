# ElasticBitAllocation fixed benchmark protocol v1

This document freezes the Stage-A reference workload and accounting contract
for issue #29. The executable implementation is
`crates/elastic-kv/src/benchmark.rs`; generate the baseline records with:

```text
cargo +1.89.0 run -p elastic-kv --example elastic_bit_allocation_baseline
```

The command evaluates a closed list of fixed candidates. It does not search,
allocate, select a winner, or change a baseline after observing results.

## Frozen workload

- protocol: `elastic-bit-allocation-v1`;
- corpus seed: `0x454c_4153_5449_4301`;
- 16 blocks, each with shape 4 × 8 and 32 canonical `f32` logical values;
- canonical denominator: 512 logical values;
- values are generated by a fixed 64-bit wrapping linear recurrence plus a
  fixed bounded pattern; every zero and every non-finite-value rejection is
  deterministic;
- no real checkpoint, tokenizer, task loss, latency, or hardware claim is
  included in Stage A.

## Fixed candidate list

The executable evaluates these candidates in this order:

1. dense F32;
2. dense BF16;
3. dense F16;
4. per-block symmetric Int4 with an F32 scale;
5. per-block symmetric Int2 with an F32 scale;
6. sparse F16 values whose absolute value reaches one half of the block
   maximum, plus packed indices and a count;
7. rank-one factors selected by a deterministic maximum-absolute pivot and
   stored as F16, plus pivot indices;
8. an eight-entry fixed scalar codebook with 3-bit indices and a codebook
   identifier;
9. an Int4 base plus F16 residuals selected when the fixed reconstruction error
   exceeds one sixteenth of the block maximum, with a residual mask.

These are reference encoders for protocol/accounting tests, not production
codecs. An implementation that cannot make a family exactly accountable must
not silently substitute it in a later result.

## Exact accounting

For every block, the result record reports:

```text
serialized_bits = raw_payload_bits + metadata_bits + serialized_padding_bits
resident_bits = serialized_bits + resident_padding_bits
```

The serialized stream is rounded to 8-bit bytes. Resident storage is rounded
to a named 256-bit allocation unit. Payload bits include packed values, factors,
or indices as appropriate. Metadata includes scales, counts, pivot indices,
codebook identity/table, and residual masks. No floating-point value is used
as authoritative storage accounting.

Reconstruction reports per-block sum of squared error, mean squared error, and
maximum absolute error against the canonical logical values. The line-oriented
record includes aggregate exact bit counts and all block metrics in stable
ordinal order.

## Scope and next gate

This Stage-A artifact freezes a runnable synthetic accounting harness. It does
not pre-register acceptance thresholds: the issue requires those thresholds to
come from selected workload and baseline evidence. Stage B must separately
freeze one named real model/checkpoint, data, runtime, software revision,
hardware, latency protocol, and task-quality metric before any allocator or
elastic-advantage claim.
